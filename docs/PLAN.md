# Mobile Agent 实施计划

更新日期：2026-09-25。本文只保留当前产品路线。

## 1. 开发原则与当前状态

先交付正式聊天 UI 和可用的多轮聊天，再在同一对话中接入本地工具，逐步增加能力。主题功能从正式 UI 首阶段实现，不留到收尾。

M0 + M1a 已完成定向验收，M1b 已由用户完成产品验收并确认进入 M2。既有自动化证据、用户验收范围与设备覆盖限制见 [验证报告](VALIDATION.md)。

范围依据：[产品定义](PRODUCT.md)、[UI 与主题规范](DESIGN.md)、[技术架构](ARCHITECTURE.md)。

## 2. 阶段总览

| 阶段 | 交付重点 | 用户可见结果 |
| --- | --- | --- |
| M0 | 固化基线、盘点当前代码 | 当前文档成为唯一方向，原型与正式入口职责清楚 |
| M1a | 正式聊天 UI、主题和基础聊天 | 可多轮聊天、压缩长对话上下文、查看历史和切换三套主题 |
| M1b | 统一工具与本地执行 | 通过对话调用一个真实本地工具，过程与结果回到聊天 |
| M2 | 文件、网络和图片能力 | 对话中处理附件、查资料并获得可用结果 |
| M3 | Root 设备控制接入 | 同一对话可组合普通工具与手机操作 |
| M4 | 恢复、复用与体验收敛 | 完整 MVP：稳定处理任务、继续工作和保存基础技能 |
| M5 | 连接器与自动化 | 连接外部服务并重复执行已验证的工作 |
| M6 | 扩展生态 | 稳定接口、开发工具与受控分发 |

M1a 就交付正式 UI；M4 是首个完整 MVP 完成点。必要权限、停止与失败处理随相应功能交付，不能等 M4 才首次加入。

- [x] 统一 AI 聊天软件定位、对话调用工具、模块解耦和单 APK Root 边界。
- [x] 确定一套布局、三套主题，以及主题切换行为。
- [x] 将主题规范收敛为语义令牌和组件约束，不长期保存易失真的静态参考图。
- [x] 核对开源图标来源，选定 Lucide 并记录许可要求。
- [x] 全量重写当前文档，不保留旧方案副本或归档。
- [x] 结合现有未提交代码确认迁移切入点，保留可用设备与存储基础。
- [x] 删除不再使用的 PrototypeScreen 与设备诊断入口，将 Root 授权移到通用设置。

M0 验证：使用进程级 `JAVA_TOOL_OPTIONS` 指定 WindowsSelectorProvider 与项目临时 socket 目录，绕过本机 JDK 回环故障；当时的 core/model/data 单元测试、assembleDebug 和 lintDebug 已通过。没有修改系统全局 Java 配置、提交 Git 或清空旧设备。后续已删除旧诊断页面与 Debug Manifest 注册。

退出条件：后续开发均能归入聊天、模型、工具、执行、数据或展示设置；Root 不作为聊天启动条件。

## 4. M1a：正式聊天 UI 与三主题

### 交付内容

- [x] 实现聊天首页、历史会话侧栏、新对话、消息流和底部输入区。
- [x] 历史会话支持长按置顶/取消置顶和确认删除；置顶状态持久化，运行中的会话禁止删除。
- [x] 建立会话/消息持久化及多轮上下文，模型支持真实文本流和正常结束/失败。
- [x] 建立独立 ContextManager，按模型窗口、输出预留与完整输入计算预算，支持自动及手动上下文压缩。
- [x] 保存带覆盖边界、原文引用和版本的结构化摘要，保留近期原文与用户关键要求，完整历史不删除。
- [x] 压缩请求自身支持分块与预算约束；失败、取消和并发补充时保留上一个有效快照与新增消息。
- [x] 实现对话内压缩状态、会话菜单入口与摘要查看；模型切换后重新检查预算。
- [x] 纯聊天不要求设备界面识别、工具计划、Root 或设备服务启动。
- [x] 建立统一消息、文件卡、工具摘要和确认组件的展示契约；未接入动作不得假装完成。
- [x] 实现 PAPER、GRAPHITE、WARM 三套颜色令牌与公共组件。
- [x] 设置 → 外观 → 主题，提供 SYSTEM 和三个固定选项。
- [x] 主题立即生效并持久化，SYSTEM 随系统解析，手动选择不被系统覆盖。
- [x] 正式主题关闭壁纸动态取色，系统栏配色与当前有效主题协调。
- [x] 保护主题切换时的草稿、附件、滚动位置、焦点与会话状态。
- [x] 从 Lucide 官方导入实际需要的图标，锁定来源版本，保存上游许可证并更新第三方声明。
- [x] 模型与高级设置作为次级入口，界面中显示真实可用状态。
- [x] 支持保存多个独立模型配置，并在聊天输入区直接切换当前模型；旧版单模型配置自动迁移。

### 验收

1. 未 Root 设备上新建对话、连续追问、接收流式回复，关闭重开后可读取历史。
2. 所有工具关闭时聊天仍可用，不出现设备授权请求。
3. 切换三套主题：同一会话布局不变，颜色即时更新，重启记住选择。
4. SYSTEM 随系统浅/深色切换；选择温暖或另一个固定主题后不被系统替换。
5. 输入长消息、附加材料、滚到历史位置再切主题，内容和位置不丢失。
6. 小屏、大字体和键盘弹出时输入和停止控件可达；颜色、图标与文案符合设计规范。
7. 使用低窗口测试配置和含已知要求的长会话触发压缩，验证关键约束、用户纠正、近期消息和来源引用仍在组装上下文中，原始记录完整可读。
8. 连续压缩后追问早期精确细节，验证可从来源取回；摘要遗漏或来源不可用时不假装记得。
9. 模拟压缩超时、取消、重启、压缩期间补充消息及切换小窗口模型：不漏消息、不发布半摘要、不发送超限输入。

退出条件：用户拿到可交互的正式聊天界面和真实聊天能力，不是仅有静态图或假回复。

## 5. M1b：工具调用与本地执行

实现状态：公共契约、模型流解析、运行时循环、Room 记录、底部批准面板和权限设置已落地；`:tools` 注册历史检索、文件、网络和设备提供者。长工具结果使用 tool_call_id 引用并可分段读取。用户已完成 M1 产品验收并确认进入下一阶段。

### 交付内容

- [x] 定义能力、工具描述、可用性、调用、结果与执行事件契约。
- [x] 模型输出支持通用 ToolCall，模型适配与具体工具实现解耦。
- [x] 注册一个真实在手机本地执行的无副作用工具，例如本地文本统计。
- [x] 运行时校验参数、能力状态和授权范围，再分派到提供者。
- [x] 执行进度、结果和错误进入原消息流，真实结果交回模型。
- [x] 实现停止、运行中补充消息及接收/待处理状态。
- [x] 适配执行持久化与必要后台运行，UI 不拥有工具执行协程。
- [x] 接入 `ask_user` 需求澄清工具；应用内和其它应用上方共用同一等待状态，回答后继续原任务。
- [x] 前移任务前台服务生命周期，授权和询问在离开 App 后通过悬浮卡处理，无悬浮权限时以通知召回。
- [x] 将后台入口重构为悬浮按钮、摘要卡、完整悬浮对话三态；完整态支持四角有限缩放、消息/授权/询问和任务优先加最近 5 个会话切换。
- [x] 工具范围面板与工具管理显示真实状态，禁用后不再允许新调用。
- [x] 将工具定义与结果纳入上下文预算，保留未完成调用/返回的关联；大输出引用化，权限与执行状态从真实记录恢复。

### 验收

- 同一会话先问答，再调用本地工具，再基于真实结果继续追问。
- 新工具只实现公共接口并注册，无须修改聊天页面或供应商适配器。
- 提供者初始化/执行失败不阻断聊天和无关工具。
- 停止后不派发新动作；在途操作结果未知时如实说明。
- 执行中发补充消息能够被运行时接收处理；切换主题不导致重复调用。
- 进程中断后保留记录，不自动重放未知副作用。
- 长工具结果触发压缩后调用链仍完整，待授权及已取消状态不被摘要改写，不重复派发已经执行的操作。

## 6. M2：首批通用能力

实现状态：文本产物、客户端联网、图片输入、SVG/PNG/GIF 本地渲染、JPG/PNG/GIF/SVG/HTML 应用内预览、图片/文本系统分享和附件清理闭环已完成。聊天中的来源卡片可打开原网页，模型结果可使用 Markdown 链接引用。首批 PDF 读取暂不纳入当前实现。

### 文件与图片

- [x] 使用系统选择器获得持久授权，支持文本、Markdown 和常见图片；图片缩放后作为多模态内容随聊天请求发送。
- [ ] 首批 PDF 文本读取。
- [x] 支持图片和文本从系统分享进入 App，由用户选择新会话或已有会话；临时授权内容先复制到受控目录。
- [x] 在授权范围内读取，默认新建结果、不覆盖原文件。
- [x] 文件产物原子发布，提供真实预览、分享、删除与继续加工。
- [x] 自包含 SVG 可直接保存或转换为 PNG；多张 SVG 帧可按逐帧时长编码为循环 GIF，并限制外部引用、帧数、像素和总时长。
- [x] 建立导入附件、图片请求缓存、工具产物和异常临时文件的独立清理策略。

### 网络

- [x] 独立搜索和网页读取工具，保存来源标题、URL 与必要摘要。
- [x] 网页内容作为不可信数据处理，限制读取大小、跳转和超时。
- [x] 资料整理结果保留可追溯来源，报告可作为文件输出。

### 验收

用户在同一聊天中提交附件、提取内容、补充网络资料并得到新文件，再提出修改。原文件保持不变；只有真实可访问的产物展示为已保存。

正式大众构建的默认模型服务需在此阶段形成可运行方案，开发配置成功不能代替默认服务已落地；不在文档中预定尚未选择的供应商和费用。

## 7. M3：Root 设备能力

实现状态：设备会话、界面识别、单步动作、最多二十步的本地批量执行、复杂轨迹、系统导航、轻量状态等待、JPEG 截图压缩、前台/后台控制条及清理路径已落地；识别节点和图片仍采用单步生命周期。悬浮窗展开后显示与聊天页同源的思考、操作和已生成正文；通用设置可统一开关 Logcat 详细日志。剪贴板、通知、深链接、系统面板、音量、显示设置和文件分享作为独立能力组接入。

### 交付内容

- [x] 保留 :device 同 APK 交付，以能力提供者接入公共工具路径。
- [x] 无打扰检测 Root 与兼容性，未知、不支持、未授权、可用、降级明确区分。
- [x] 只在用户主动打开通用设置的 Root 开关时请求授权；本机不可用时禁用开关。
- [x] 映射设备会话、界面识别、受控动作、应用启动和清理工具。
- [x] 复用同一会话消息、执行、范围授权、停止与结果系统。
- [x] 虚拟屏内部管理，前台通知与立即停止可用。
- [x] 设备调用与普通文件、网络工具可在同一请求中组合。
- [x] Root 工作进程与普通进程按类型化接口隔离，不产生独立安装包。

### 验收矩阵

| 条件 | 结果 |
| --- | --- |
| 已确认未 Root | 设备控制不可用，聊天、文件和网络仍正常 |
| Root 状态未知 | 通用设置显示检测中，完成前开关不可编辑 |
| 已 Root、未授权 | 启动无弹窗，用户打开通用设置开关时请求 |
| 已授权且自检通过 | 对话中完成受支持应用操作并返回真实证据 |
| 执行期间权限失效 | 停止后续设备动作，解释结果，清理会话 |
| ROM 或应用不支持 | 返回具体限制，不盲目尝试动作 |

必须验证从文件读取到手机应用查询再返回结果的完整会话；同一过程中切换主题不会重复执行或重建设备会话。
