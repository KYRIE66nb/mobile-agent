# Mobile Agent UI 与主题规范

更新日期：2026-09-25。状态：统一 UI、三套主题与产品文案的实现基线。

## 1. 设计决定

产品主体是 AI 聊天。采用一套聊天布局、一套组件、一套交互，以及三套可切换的颜色主题。

当前视觉基准是白底大留白、低对比度细边框、轻阴影圆角输入区、蓝色单一强调色、线性图标和抽屉式会话列表。深色与温暖主题只替换语义颜色，不分别复制页面、改变消息间距或移动输入控件。

静态设计图和阶段性截图会随实现快速失真，因此不作为长期规范文件保存。布局、状态和视觉判断以本文的文字规则、语义令牌、当前组件实现和当次验证结果为准；演示内容不能替代真实运行状态。

## 2. 布局与导航

设计参考视口为 390 × 844 逻辑单位，Android 实现使用 dp/sp，自适应实际窗口与系统安全区。概念图没有系统栏，正式应用必须正确处理状态栏、手势区域、键盘与横竖屏。

### 2.1 聊天主界面

按从上到下的固定层次组织：

1. 顶部栏：左侧历史会话，中央按需显示会话标题或回复状态，右侧新对话与会话菜单。
2. 可滚动消息区：空白引导或当前会话内容。
3. 底部输入区：草稿、附件、本会话工具范围、思考强度、模型与发送/停止。

顶部栏高度基准 56 dp，图标点击区域至少 48 × 48 dp。新对话创建新的上下文，切换或创建会话不等于取消其它正在执行的工作。

会话标题较长时单行省略，可通过会话菜单查看和修改。标题、历史入口与新对话的位置不随主题改变。

### 2.2 空会话

主要文案为“你好，我能帮你做什么？”，左侧配同一套蓝色线性品牌图标。

引导在消息区中部偏上居中排版，输入区始终位于底部。空会话保持大面积留白，不放功能卡片或预设问题。

不放 Root 状态大卡、设备调试按钮、API 配置表单或成组功能宫格。

### 2.3 历史会话侧栏

侧栏包含品牌标识、新对话、搜索、置顶/最近会话、工具、设置和本机数据说明。新对话使用白色胶囊按钮与轻阴影；历史条目展示标题和必要的置顶、运行中/等待处理标记，选中项使用浅色块，不为每行套独立卡片。长按历史条目打开操作菜单，可置顶/取消置顶或删除；删除前必须二次确认，正在回复的会话需要先停止。

关闭侧栏后回到原会话，恢复草稿与阅读位置。侧栏不是另一套任务管理系统。

### 2.4 次级页面

| 入口 | 内容与返回行为 |
| --- | --- |
| 输入区“工具” | 本会话可使用的能力与范围，不能绕过系统权限；关闭面板回到输入区 |
| 工具管理 | 按能力组管理启用状态与调用授权；设备不可用时只显示“请先授予 Root 权限”且控件不可编辑 |
| 输入区“思考” | 选择后续请求使用的思考强度；“关闭”为内置默认值，会明确关闭深度思考，“不指定”则由模型服务决定；候选等级和上次选择随当前模型配置保存，切换模型后显示对应等级 |
| 输入区模型选择 | 直接列出所有已配置模型并标记当前项；模型名前用圆形进度环显示上下文占用，点击后以深色锚定气泡展示输入、最大输出预留、总窗口、剩余量以及实际/估算状态，达到 80%/95% 时分别使用警告/错误色；切换影响后续请求，不中途替换已经发出的模型请求，菜单底部进入模型管理 |
| 文件卡片 | 预览或系统分享，返回后保持会话上下文 |
| 设置 | 独立页面内使用“通用 / 个性化 / 语音 / 模型服务 / 数据管理 / 关于”六个分栏，当前分栏进入页面时自动滚动到可见位置，返回后恢复原会话；个性化设置保存用户长期偏好、习惯和回复方式，随新的模型请求发送，但不写入对话历史；关于页展示 APP 版本、作者、开源地址，并在鸣谢区域列出主要开源库的版本、许可证与上游链接 |

| 设置 → 通用设置 | 语言（跟随系统 / 中文 / English）、三套固定主题、跟随系统、单轮最大步骤（默认 99，范围 1–999；输入实时保存、点按别处失焦）、悬浮助手与 Root 权限开关，见第 5 节 |

## 3. 消息流与执行状态

### 3.1 消息样式

- 用户消息右对齐，使用 userBubble 色与适度圆角，最大宽度约消息区的 85%；附件位于同一消息内。
- AI 回复左对齐，直接呈现在背景上，正文清晰可选中；不把每段文字装进独立卡片。
- 用户消息、AI 正文和展开后的思考内容均支持长按选中文字并使用系统复制操作；链接点击和代码块横向滚动保持原交互。
- 模型返回独立思考流时，在 AI 名称下显示“思考 · 持续了…”；生成中和完成后都默认折叠，用户可按轮次手动展开。每次模型执行轮次独立保存并按“思考、该轮工具调用、该轮正文”显示，然后再进入下一轮；轮次之间换行，但不额外添加步骤编号。
- 连续 AI 内容不重复显示大头像，角色通过布局及必要的小标签区分。
- 工具状态和文件结果放在所属模型执行轮次中，位于该轮思考之后、正文之前；状态卡显示实际工具名称与结果摘要，等待批准的调用不在消息列表插入卡片。
- 工具管理按对话记录、文件、联网访问、手机操作、剪贴板、通知、系统功能和询问用户分组，不逐项展示底层函数。一般能力提供启用开关及“每次询问/始终允许”；“询问用户”只提供启用开关，因为它本身就是等待用户回答，不能再套一层工具授权。当前不可用时整组控件禁用并显示原因，降级能力显示缺少的系统授权和可执行入口。需要确认的调用从底部说明工具、实际动作和访问范围，只展示用户可读的参数摘要，不展示原始 JSON、内部 ID 或协议字段，并提供“不允许”“仅本次允许”和“始终允许”。“始终允许”按工具组持久保存并可撤销；前台或后台等必须由用户选择的运行方式不会随之自动决定。
- 网络搜索完成后，在所属工具步骤下方显示紧凑来源卡片；卡片包含序号、标题和摘要或域名，点击打开原网页。最终回复中的 Markdown 来源链接同样可点击，来源随工具记录恢复。
- Markdown 支持标题、段落、列表、链接和代码块。长代码块可水平滚动；宽表格进入横向容器或详情，不挤压正文。
- 文件、代码等需要独立操作的对象可使用轻量边框卡片，避免卡片层层嵌套。

用户正在阅读旧消息时，新增内容不强制滚到底部；提供“有新消息”或回到底部入口。已处于底部时随流式输出自然跟随。

### 3.2 工具过程

默认使用回复内紧凑的状态摘要，显示正在做什么，可展开关键步骤；不要把原始参数和大输出直接打印在聊天正文中。

| 状态 | 展示 | 交互 |
| --- | --- | --- |
| 准备中 | 准备原因与文字 | 可停止等待 |
| 执行中 | 活动指示与动作摘要 | 展开过程、停止；不伪造百分比 |
| 等待确认 | 底部范围与动作确认面板 | 不允许、仅本次允许或始终允许；长期授权按工具组保存 |
| 等待补充 | AI 提问或需用户处理的具体原因 | 正常输入回复或完成操作后继续 |
| 已完成 | 完成标记与真实结果摘要 | 展开详情、打开结果 |
| 未完成 | 错误摘要和可行动原因 | 安全重试或调整；未知外部写入不直接重放 |
| 已停止/已中断 | 明确文字，不使用成功标记 | 保留已有内容，并可继续对话 |

状态颜色必须配合文字与图标。工具完成不等同于整个请求完成，仍需 AI 解释或交付结果。

AI 只在缺少的选择会实质改变结果时调用 `ask_user`，一次询问一个明确问题，可提供最多六个互斥选项和自由输入。应用内使用独立底部询问面板；用户选择或输入后，答案作为工具结果返回同一轮任务。关闭面板表示“暂不回答”，不视为拒绝其它工具，也不授予权限。询问不得索取密码、验证码、支付信息、API 密钥或账号安全凭据。

任意 AI 任务开始时即建立前台服务承载，不能等设备会话创建后才启动。通用设置提供“常驻悬浮助手”开关；开启后即使没有任务也保留低优先级常驻通知，用户离开 App 后显示悬浮按钮，并在设备重启后恢复空闲入口。关闭常驻只移除空闲入口，任务、授权和 AI 询问仍可临时启动服务。没有悬浮窗权限时，高优先级通知只返回原对话，不在通知操作中直接批准。悬浮输入窗口使用安全标志，避免其内容进入系统截图。

聊天输入区的麦克风按钮在文本输入与语音输入之间切换；语音模式使用明确的“按住说话”操作面，按下成功开始录音时提供一次短促触觉反馈，松开结束，录音、转写和失败状态就地反馈，不额外堆叠说明卡。悬浮按钮以长按触发同一语音输入并使用相同触觉反馈：停留在中区时松手转写并发送到当前会话，上滑进入取消区，下滑进入新会话发送区，跨区时用图标、无障碍描述和轻触觉反馈确认；回到中区恢复默认发送。长按阈值前仍可拖动，短按仍用于展开。未配置当前语音服务或缺少麦克风权限时进入“设置 → 语音”，不振动也不静默失败。

“语音”设置用等高的两行供应商卡展示 OpenAI 兼容格式和科大讯飞兼容格式，当前项仅在卡片右上角显示紧凑标签。选中卡片后在下方编辑对应字段，可分别保存、测试连接并设为当前；尚未完整配置的格式不能切为当前，避免录音后才发现凭据缺失。

悬浮助手采用三种展示状态。状态 1 是贴边的单体状态胶囊：保持纤细的单一轮廓和至少 48dp 触控区，不附加连接条，并把图标与主要抓握区域放在系统侧边手势热区的内侧；拖动时可在安全区域内移动，松手后吸附最近的屏幕边缘。它用图标、颜色和无障碍文字共同表达空闲、执行、完成与待处理状态；空闲保持机器人图标，任务执行或语音转写中使用持续旋转的进度环，完成继续显示勾选图标。向屏幕内拉动或点击后进入状态 2 单行摘要卡，整张卡片均可双向拖动，显示任务标题和当前步骤，右侧只保留展开及必要时的停止操作；将卡片向最近的屏幕外侧继续推可回到状态 1。无任务且 20 秒没有操作时自动收起。新任务开始、任务完成、出现授权或 AI 询问时，低层状态自动提升到状态 2，但不打断用户正在使用的状态 3。

状态 3 是紧凑的完整悬浮对话：显示原对话的消息、思考与工具状态，可发送补充消息、停止任务、批准/拒绝授权及回答询问。连续成功的工具步骤默认折叠成“已完成 N 步”，执行中、失败、拒绝和中断状态保持展开，避免过程日志淹没当前任务。顶部可切换“任务会话”和最近 5 个会话；等待授权、等待回答及运行中的会话始终优先显示，不占最近 5 个名额，其他会话仍在 App 主页管理。用户可拖动顶部移动窗口；到达左右安全边界后继续向外推并松手，会直接吸附为对应侧的状态 1。右下角唯一的缩放入口用于在安全区内调整大小；继续缩小越过下限时折叠为状态 2，达到上限后继续外拖则打开 App 主页。顶部图标可收起为状态 2，或进入当前对话并把后台悬浮层恢复为适当的低层状态。

首次开启手机操作会话时不再弹出前台/后台二选一。普通指令和侧边悬浮按钮语音指令都由 AI 结合用户要求与任务目标选择模式：明确说“前台”“主屏”“可见操作”或“后台”时直接照做；未声明时，打开或切换应用、展示页面及需要用户看到屏幕结果的任务使用主屏，可在隔离屏独立完成且不应打扰当前屏幕的任务使用后台。模式选择不调用 `ask_user`，但实际设备动作仍遵循工具授权策略。Android 13 及以上的通知权限不与工具授权混同。持续通知提供返回原对话和停止入口。悬浮层不显示设备截图或虚拟屏画面；Android 14 及以上的主屏识别优先直接截取当前目标应用窗口，并只读取该窗口的节点，悬浮助手和其它上层窗口不进入图片。窗口截图不可用时才短暂移除悬浮层并回退整屏截图；坐标动作期间仍短暂让出悬浮层，避免点击命中控制条，恢复后保持原展示状态与位置。

### 3.3 结果与后续对话

文件卡片展示文件类型、名称、简短元数据、预览和分享；图片附件直接显示缩略图，并可不输入文字单独发送。结果保留上下文，用户可以直接说“改成表格”或“再加一项”。从其它 App 分享图片或文本时，使用底部面板选择新会话或已有会话，内容先进入草稿，不自动发送。

预览和分享按钮只有在文件可用时才启用。文件生成失败不能显示为已保存，未授权工具不能显示为已执行。

### 3.4 上下文压缩反馈

上下文压缩作为长对话的辅助状态，不新增主页面或打断式弹窗。

- 自动触发时在当前回复附近显示“正在整理较早的对话…”，输入框仍可使用，新消息显示待处理；停止入口仍可取消当前等待/生成。
- 完成后轻量提示“较早对话已整理，完整对话记录仍保留”，随后继续本轮回复；工具循环中达到阈值则显示“上下文已自动压缩，任务继续执行”；不把压缩摘要伪装成用户消息或 AI 最终答复。
- 对话菜单提供“整理较早对话”和“查看对话摘要”。主动整理只对已完成部分生效，当前无适合整理内容时说明原因，不生成无意义摘要。
- 摘要详情展示保留的要点、覆盖范围和来源入口；如显示 token 用量，必须标明估算或实际计数，不能编造精确百分比。
- 原始消息仍可在聊天历史中查看，压缩不折叠或删除用户正在阅读的历史，不改变滚动位置。
- 失败时显示“整理未完成，对话记录未改动”；能够沿用原上下文则继续，否则保留草稿并提供重试或调整输入的入口。
- 三套主题共用上述交互，状态文字采用统一语义色；压缩不能被误显示为工具执行成功。

## 4. 输入区组件

输入框固定在键盘上方，使用统一浮动圆角容器，左右 16 dp 外边距。输入正文与底部工具行分层，所有主题保持相同结构。

| 状态 | 行为 |
| --- | --- |
| 空白 | 显示占位文案“发消息，或描述你想完成的事”，不可提交空消息 |
| 草稿 | 支持多行、附件预览和移除；输入至多占约 6 行，随后内部滚动 |
| 模型回复/工具执行中 | 输入仍可编辑，右侧保持独立且可见的停止按钮 |
| 执行中有补充草稿 | 除停止外显示“发送补充”动作；不得让同一图标同时代表发送和停止 |
| 补充已发送 | 原消息流显示“待处理”，运行时接收后更新状态 |
| 正在停止 | 显示“正在停止”，防止重复触发；不承诺撤销已经完成的外部操作 |
| 执行结束 | 恢复常规发送入口，草稿与附件保持 |

附件入口使用 plus；工具使用 sliders-horizontal；思考强度使用 brain-circuit；模型使用 database 与当前配置名称。思考强度在紧凑菜单中选择，默认显示“关闭”；“关闭”会发送协议值 `none`，“不指定”则不发送思考强度字段，选中值随模型配置保存。模型点击后先显示可直接切换的模型列表，再从底部入口进入完整模型管理。发送使用 arrow-up，停止使用 square，两者语义不能只靠颜色区分。

软件键盘回车默认换行，发送通过明确按钮操作。输入框和消息正文使用系统输入法与选择行为，避免自制键盘。

## 5. 主题功能

### 5.1 选择与持久化

“设置 → 通用设置 → 主题”以图标卡片展示主题选择：

| 选项 | 存储值 | 生效结果 |
| --- | --- | --- |
| 跟随系统（默认） | SYSTEM | 系统浅色用 PAPER，系统深色用 GRAPHITE |
| 留白对话 | PAPER | 固定浅色配色 |
| 深色工作台 | GRAPHITE | 固定深色配色 |
| 温暖手记 | WARM | 固定暖色配色，不随系统改换 |

只有三套实际配色；“跟随系统”是选择策略，不是第四套配色。不额外生成温暖深色等未经确定的变体。

选择后全局立即更新，并持久保存；返回聊天和重启 App 后保持选择。手动主题不被系统深浅色或壁纸动态颜色覆盖。首版关闭 Material 动态取色，保证已确定的三套颜色可复现。

主题是全 App 设置，作用于聊天、侧栏、工具面板、设置、弹层、文件预览外框和错误状态。图片、截图、文档原内容不强行染色。

切换主题不得重启任务、重新发送消息、重新连接模型、丢失输入焦点或重建 Root 会话。

Root 权限使用紧凑设置行，不再提供设备诊断页面。打开开关时才请求系统 Root 授权；本机没有可执行的 Root 环境时，开关关闭并处于不可编辑状态。用户开启后的选择持久保存；冷启动尚未建立 Root Shell 时显示为等待使用时确认，不能误判为授权丢失。关闭开关会停止应用继续使用 Root，并释放当前设备会话。

## 6. 字体、间距和状态

### 6.1 排版与尺寸

| 项目 | 统一基准 |
| --- | --- |
| 字体 | Android 系统无衬线，中英文均使用系统字体回退；代码内容使用等宽 |
| 空会话标题 | 28 sp / 36 sp，较强调字重 |
| 顶栏与页标题 | 20 sp / 28 sp，中等字重 |
| 消息正文、输入 | 16 sp / 24 sp |
| 工具摘要与操作文字 | 14 sp / 20 sp |
| 附属元数据 | 12 sp / 18 sp，不承载核心状态或唯一操作 |
| 间距体系 | 4、8、12、16、24、32 dp |
| 页面水平留白 | 常规 16–24 dp，小屏优先保证正文宽度 |
| 消息组间距 | 24 dp；同组内容 8–12 dp |
| 输入容器圆角 | 28 dp |
| 用户气泡圆角 | 18 dp |
| 文件、审批等对象圆角 | 12 dp |
| 图标 | 常规 20–24 dp，使用同一线宽体系 |
| 操作点击范围 | 至少 48 × 48 dp，图标视觉尺寸可小于点击范围 |

适配大字体时允许换行和控件增长，不强行固定消息高度。三套主题不能分别调整字重、间距、头像规则或气泡形状。

### 6.2 组件状态

按钮、输入、主题选项和可展开行至少覆盖正常、按压、聚焦、禁用、加载及错误状态。当前选中的主题同时使用标记与文字说明。

按压采用局部状态层；禁用动作保持可解释的原因，不让整张聊天页面降透明度。颜色和内容过渡约 150–200 ms，尊重系统减少动画设置，不添加无用途的呼吸光效。

TalkBack 可读出发送、停止、附件、工具名称与执行状态。状态更新有节制地播报，不逐字播报所有流式输出。危险动作使用明确文案，不只放一个红色图标。

### 6.3 产品文案

- 用户界面统一使用“对话”；“会话”只用于内部协议、设备执行和代码命名，不直接展示给用户。
- 用户界面统一使用“工具”，避免同时使用“工具与能力”“能力调用”等近义名称。
- 授权统一使用“每次询问”“仅本次允许”“始终允许”“不允许”。手机操作方式使用“可见操作（主屏）”“后台操作”。
- 状态统一使用“准备中”“等待确认”“执行中”“已完成”“未完成”“未授权”“已停止”“已中断”。思考流使用“思考 · 进行中”或“思考 · 持续了 N 秒”。
- 错误先说明影响，再提供可执行的下一步。界面不展示堆栈、HTTP 响应正文、JSON 解析细节、内部 ID、URI、Binder、Surface 或 displayId。
- API key 在用户界面写作“API 密钥”；Token 作为配置单位时保留英文写法。
- 按钮使用动作词，例如“保存设置”“立即清理”“返回对话摘要”，避免“确定”“处理”等含义不清的词。
