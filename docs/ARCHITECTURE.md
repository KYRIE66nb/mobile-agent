# Mobile Agent 技术架构

更新日期：2026-09-25。状态：目标实现；以 [产品定义](PRODUCT.md) 和 [UI 与主题规范](DESIGN.md) 为输入。

## 1. 架构目标

提供可独立使用的 AI 聊天核心，并通过公共接口接入本地及远端工具。聊天、模型供应商、运行时和功能模块分别承担职责；没有工具或没有 Root 时，普通聊天仍可运行。

同一 APK 内包含全部首版模块。设备控制单独检测 Root 和兼容性；主题属于展示设置，不参与模型决策或工具调度。

## 2. 职责与依赖

| 层 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 聊天 UI | 输入、消息流、历史、进度、结果和必要确认 | 直接调用设备服务或具体工具 |
| 会话与执行运行时 | 上下文、消息接收、模型循环、工具分派、取消和恢复 | 绑定某个模型供应商或界面组件 |
| 上下文管理 | 输入预算、消息选择、摘要压缩、原文引用与恢复 | 删除原始历史或授予工具权限 |
| 模型适配层 | 把不同服务响应归一为文本流、工具调用及结束/错误事件 | 执行 Android、文件或 Root 操作 |
| 工具公共接口与注册表 | 工具描述、能力状态、执行契约和结果类型 | 包含某项业务工具的内部逻辑 |
| 各能力提供者 | 文件、网络、图片、设备等具体操作 | 直接调用彼此内部实现或控制聊天页面 |
| 数据与设置 | 会话、消息、执行记录、文件索引、授权、主题与密钥引用 | 用页面内存状态替代持久化事实 |
| 应用装配 | 注册实际模型、工具、存储与服务实现 | 把所有业务重新塞入全局控制器 |

运行关系：聊天提交消息给运行时；运行时通过模型接口获得回复或工具调用；调用经过注册表与本地策略检查后交给对应模块；模块返回真实结果，运行时继续请求模型并发布事件；UI 观察这些记录。

主题和 App 语言选择独立进入展示层。主题切换只更新语义颜色；语言通过 AppCompat 应用级 Locale API 选择跟随系统、中文或英文，两者都不参与这条执行链路。

## 3. 现有模块与演进位置

当前 Gradle 包含 :app、:agent-core、:model、:device、:data、:tools，维持渐进迁移。

| 模块 | 目标职责 |
| --- | --- |
| :app | Compose 聊天、导航、主题与组件、服务入口和依赖装配 |
| :agent-core | 纯业务会话/执行契约、上下文管理、模型接口、调度、状态规则及跨模块中英文选择 |
| :model | 模型服务适配、流式响应、工具调用格式转换 |
| :data | Room、设置持久化、授权记录、产物索引及密钥保护 |
| :device | Root 状态检测、设备会话、界面/节点识别、语义动作与复杂触控 |
| :tools | 历史、文件、SVG/PNG/GIF 图像渲染、网络、设备、剪贴板、通知、系统和询问用户工具，以及能力组启用与权限持久化 |
| :capability-api | 按需抽出的公共工具接口，供运行时和各提供者依赖 |
| :capabilities-core | 首批文件、网络、图片等提供者；内部仍分别注册、测试与初始化 |

新增两个目标模块不是开工前置要求；先建立正确接口和可验证流程，再决定物理拆分。不为尚未交付的功能建立空模块。

### 解耦约束

- 聊天 UI 不导入具体 DeviceGateway、网络抓取器或文件执行器。
- 模型适配器不依赖具体工具实现；更换供应商不要求重写工具。
- 提供者声明依赖，跨能力组合由运行时调度。
- 新工具实现公共接口并注册后，就能通过通用进度与结果组件接入聊天。
- 可选结果渲染器不能接管整个聊天、输入区或授权逻辑。
- 模块初始化失败转为能力不可用，不阻止基础 App 启动。
- 模块自身释放资源，运行时统一传播取消与超时。
- Root 只存在于设备模块及其受控进程边界。

## 4. 会话与执行

### 4.1 核心记录

| 记录 | 内容 |
| --- | --- |
| Conversation | 标题、创建/更新时间、置顶状态、会话配置与上下文关联 |
| Message | 所属会话、角色、正文、按执行步骤保存的思考内容及总耗时、附件引用、顺序、生成/接收状态 |
| ContextSnapshot | 压缩摘要、覆盖的消息边界/版本、来源引用、生成模型、预算估算与摘要格式版本 |
| Run | 本轮执行及触发消息、当前状态、范围、模型与取消标记 |
| TaskEvent | 关联 Run 的计划、工具状态、审批、错误与结果引用 |
| ToolCall | 调用 ID、工具 ID、参数、执行状态和结果引用 |
| Artifact | 文件名称、类型、位置、版本/派生关系、所属会话与执行 |
| Approval | 具体动作、范围、有效期和决定 |
| CapabilityState | 可用性、配置引用和最近检测结果 |
| AppearanceSettings | 用户主题、日志与常驻悬浮助手选择，与会话、执行记录分开保存 |

一段会话包含多轮 Run。一轮可以只生成普通回复，也可以进行多步工具执行；Task 是对执行工作的产品描述，不要求普通聊天先创建独立任务实体或进入任务页面。

消息正文只保留一份持久化事实。TaskEvent 引用消息和产物，不重复保存一套可能分歧的聊天正文。大输出写受控文件区，事件保存摘要与引用。

### 4.2 模型与工具循环

1. 保存用户消息，加载可用模型及允许工具描述，由上下文管理按预算组装消息，必要时先压缩。
2. 模型返回正文增量、可选思考增量、工具调用或结束事件。
3. 每次模型请求保存为一个 AssistantStep，逐步写入该轮思考、工具调用记录 ID、正文和思考耗时。
4. 工具调用完成参数、可用性与权限检查后分派执行；`ask_user` 由独立问题代理发布等待项，不进入通用工具授权。
5. 工具状态写入事件，真实结果关联原调用 ID 后交回模型。
6. 模型继续回复或调用下一个工具，直至结束、等待用户、停止或失败。

页面按 AssistantStep 顺序渲染“思考、工具调用、正文”，再进入下一轮，避免把同一回复中的所有思考、工具状态和正文分别汇总后打乱关系。旧消息没有轮次映射时继续使用旧版聚合展示。

普通聊天走文本路径，不启动设备服务，不强制计划或授权。工具返回成功只代表本次操作成功，用户需求是否完成仍由后续回复与验证说明。

### 4.3 状态与取消

Run 使用准备、生成/执行中、等待授权、等待用户、已暂停、成功、失败、已取消、已中断等明确状态。模型文本生成状态和单个 ToolCall 状态分别记录，不能把工具完成直接映射为会话关闭。

停止请求立即设置取消标记并停止派发后续工具；支持取消的在途操作发出取消。已产生的外部副作用不能假称撤销，无法确认结果的操作记录为待核实。

切换会话或主题不取消 Run。Activity 销毁不拥有执行协程的生杀权；任务生命周期由运行时及相应服务承载。

`UserQuestionBroker` 是 Application 级单一状态所有者。应用内底部面板和后台悬浮卡只观察同一份问题状态，并以同一个问题 ID 竞争完成同一 `CompletableDeferred`，因此重复点击或界面切换不会把两个答案返回模型。任务取消会取消等待并清理问题；进程结束仍按中断处理，不跨进程自动重放。

前台服务随任意活跃 Run 启动，而非随设备 session 延后启动；用户也可以选择让它在空闲时常驻。服务合并观察活跃 Run、工具审批、用户问题、设备模式和持久化的常驻开关。用户开启常驻后，开机完成广播只恢复前台服务、贴边入口和通知，不恢复或重放上次未完成的 Run。App 不可见且有系统悬浮权限时，展示层由独立三态状态机管理悬浮按钮、摘要卡和完整悬浮对话；业务事实仍只来自运行时、会话存储和问题代理。任务开始/完成、工具审批和用户问题只会把低层状态提升为摘要，不会覆盖用户正在操作的完整对话。无悬浮权限时使用独立高重要性通知频道召回原对话，通知不包含直接授权动作。

完整悬浮对话观察所选会话的 Message、ToolCall 和草稿，可发送消息、停止当前任务并完成同一份授权或询问。会话切换器先列出所有等待授权、等待回答及运行中的会话，再列出最多 5 个按更新时间排序的其它会话；切换只改变当前观察与输入目标，不取消任何 Run。窗口尺寸和展示状态属于服务内的展示状态，不另存任务副本；四角缩放越过最小阈值回到摘要，越过保留操作余量的最大阈值打开主页。

### 4.4 运行中补充与恢复

补充消息先持久化并显示待处理。运行时在安全边界接收，处理后更新状态；不会重放已经完成的外部操作。

进程重启时将未完成的本地执行标记为中断或结果未知。恢复前重查可用性、授权与外部状态；设备控制创建新会话并重新识别界面。重试不能继承过期授权或重复未知结果的发送、发布和删除。

### 4.5 上下文管理与压缩

ContextManager 是运行时中的独立职责，通过模型接口请求摘要，通过存储接口读取原文；不与聊天 UI、Root 或具体工具绑定。没有工具的普通聊天也能压缩上下文。

#### 预算与触发

每次模型请求前估算完整输入：系统与应用指令、工具定义、摘要、消息、附件及工具结果。输入预算等于模型上下文窗口减去本轮输出预留和安全余量；同时遵守供应商独立输入上限（若存在）。

优先使用对应模型的 token 计数能力，无法精确计数时采用保守估算并标记估算值；中文、工具 Schema、图片等不能简单当成字符数。模型窗口与输出限制来自已验证的模型配置，未知时使用明确保守配置，不假定无限上下文。

工程初始策略：预计输入达到可用输入预算的 80% 时尝试压缩到 60% 以下；阈值作为可调策略，不对用户承诺固定压缩率。每次工具结果返回、切换模型或工具集合变化后重新预算，不能只在用户发送新消息时检查。

#### 上下文组成

提交给模型的工作上下文由当前有效的系统/应用指令、必要工具定义、历史结构化摘要、近期完整消息及当前执行所需原文组成。用户最新请求与明确约束保留，运行时状态从真实记录组装。

摘要至少包含：

- 用户目标、约束、偏好、纠正与已作出的决定，区分用户要求与 AI 建议。
- 已确认事实与来源，区分推测、未验证内容和过期结论。
- 已完成步骤、失败原因、待办事项、未解决问题及最后执行位置。
- 关键工具结果、文件/产物引用与必要版本、相关原始消息 ID。

摘要只是历史内容的派生表示，不提高内容的指令优先级；文件、网页或工具输出中的指令不能借摘要变成系统要求。有效授权、取消标记与执行状态始终以结构化记录为准，不以摘要文字为准。

#### 压缩边界与一致性

1. 选择较早且已完成的连续消息前缀，只压缩可安全替换的完整对话/工具调用单元；近期消息按语义完整性与预算共同保留，不只机械保留固定轮数。
2. 未完成的工具调用、对应返回与待授权动作保持关联，不拆散调用 ID 与结果；在运行时的模型请求边界执行压缩，不为压缩重放任何工具。
3. 为摘要请求本身单独计算预算。过长原文分块归纳再合并，不能把已超限的整段历史再次发给摘要模型。摘要请求不提供可执行工具。
4. 摘要结果需检查结构、覆盖范围、关键约束引用和目标预算后，原子保存 ContextSnapshot 并切换活动引用。结构检查不能保证语义无损，重要事实仍需按来源核对。
5. 压缩期间新增消息继续持久化，作为边界之后的原文追加；提交摘要时校验被覆盖消息的版本，避免漏掉用户新要求或重复计入消息。
6. 中断、取消或摘要失败时不发布半成品，继续保留原始消息和上一个有效快照。恢复后检查快照版本及来源边界；历史编辑或删除时，覆盖相关内容的摘要必须失效或重建，不能恢复已删除内容。

多次压缩保留来源引用及覆盖边界，不只无限转述上一份摘要。需要时从仍保留的原始记录按相关范围重建，减少累积失真。摘要属于当前会话，不默认转成跨会话长期记忆。

#### 大输出与失败处理

文件、用户附件及工具大输出保留在其受控存储中，上下文使用摘要、引用与按需选取的片段。每次设备界面识别返回的节点和图片只供紧接着的一次模型决策使用；该次决策结束后，内存和工具记录中的节点结果替换为失效占位符，图片从请求中移除，后续动作必须重新识别。精确引用或重新处理持久文件时在当前授权范围内取回原内容，来源已清理或权限失效时说明限制。

压缩失败且原上下文仍在预算内，可以继续使用原上下文；否则在对话中提示并等待重试、缩小输入或选择可用模型，不静默截掉关键要求。单条超大附件、不可压缩的工具定义或当前必要内容已经占满预算时，先分块读取或缩小工具范围；仍无法满足时明确阻塞原因。

对确定的上下文超限错误，仅在尚未派发新工具时允许有界地重新预算/压缩后重发模型请求，禁止无限重试或重放外部操作。

记录压缩次数、前后估算用量、耗时、摘要版本与失败原因，不把完整摘要和原文写入普通日志。压缩会消耗模型请求时间和 token，不能宣称压缩本身没有成本或天然降低每次请求费用。

## 5. 公共工具契约

### 5.1 描述与结果

能力描述包含稳定 ID、显示名、用途、版本、当前可用性、工具列表与配置入口。

工具描述包含：

- 工具 ID、说明和输入/输出 Schema。
- 执行位置、需要的权限、支持范围与可用性条件。
- 副作用等级、超时、取消及重试语义。
- 用户可读的执行摘要。
- 执行接口及结构化结果、错误、文件引用。

模型提出 ToolCall，实际执行由 App 完成。“本地工具”意味着执行在手机上，不意味着模型必须本地运行，更不意味着工具必须具有 Root。

### 5.2 可用性

| 状态 | 含义 |
| --- | --- |
| CHECKING / UNKNOWN | 正在检查或暂不能判定；不能当成已确认可用 |
| AVAILABLE | 当前范围内可执行 |
| NEEDS_PERMISSION | 需要文件、系统、账号或 Root 授权 |
| NEEDS_SETUP | 需要配置服务或执行环境 |
| DISABLED | 用户已关闭 |
| UNSUPPORTED | 已确认设备、系统或当前环境不支持 |
| DEGRADED | 部分可用，需声明具体限制 |

向模型提供工具时先过滤本会话允许且可用的工具；实际调用时再次检查，防止状态在两次检查之间变化。不可用能力由对话提示或工具管理提供启用路径，AI 不能绕过关闭状态执行。

### 5.3 本地策略

权限判断由确定性代码完成。参数超出批准范围时重新申请。

基础副作用等级为 READ、LOCAL_WRITE、EXTERNAL_WRITE、DESTRUCTIVE；Root 等特权要求作为独立条件叠加检查，避免用“已获 Root”覆盖具体动作权限。

- 已授权范围内的读取与 App 工作区内正常结果生成可按对话策略执行。
- 外部写入和破坏性动作执行前确认相应范围。
- 永久授权按能力组持久保存并可撤销；需要用户选择的运行方式以及另行定义的高风险动作仍单独确认。
- 网页、文件、工具返回的文本视为数据，不能替换系统指令或增加权限。

## 6. Root 设备模块

保持同 APK 的 :device 模块。RootService 可在独立工作进程中通过 Binder/AIDL 提供类型化操作，校验调用方；这属于内部隔离，不要求另装应用。

设备模块负责检测 Root、系统兼容性和授权状态。启动不触发 su 授权弹窗；通用设置读取当前状态，且只在用户打开 Root 开关时触发授权。开关选择持久保存；新进程尚未建立 Root Shell 时保留开启状态，实际使用时再确认系统授权。本机没有可执行的 su 环境时开关禁用。关闭开关会阻止新设备会话并清理当前会话。启动应用只依赖活动设备会话和应用列表返回的真实包名；点击、输入、滑动等界面动作必须绑定最近一次界面识别的准确 ID，动作执行后该识别结果立即失效。

暴露受控的会话创建、应用列表读取、界面识别、节点语义动作、坐标动作、复杂触控、文本输入、系统导航、应用启动、批量执行与关闭。批量执行器在本地为每个步骤轻量重新读取节点，按文字、描述或 view_id 重新定位并验证前台应用，不复用旧 node_ref；最多二十步且声明时长不超过六十秒，任一步失败立即停止并返回最新界面。识别同时返回临时截图、坐标范围和节点快照；截图以 JPEG 质量 82 编码但保持原坐标尺寸，批量步骤与状态轮询只读节点，仅在最终或失败时编码一张截图。截图只进入紧接着的一次模型请求，不写入数据库；模型完成该次决策后，截图移除且节点结果替换为占位符。

应用列表返回本机具有启动入口的应用名称与真实包名；启动动作直接使用列表返回的包名，不维护固定应用白名单。每次界面动作关联当前会话及最近识别结果，防止使用过期坐标或节点。语义点击和滚动优先按稳定节点引用执行；坐标只作为没有语义节点时的回退。复杂触控以最多十条轨迹、五百个点和十秒为上限，同一开始时间的轨迹并行执行，可表达画板连续笔画和双指缩放。等待工具在有限超时内轮询文字、节点或前台应用状态，并把最终识别结果交给紧接着的一次决策。虚拟屏由设备模块按支持情况管理并释放，AI 无需选择 displayId。

设备工具可以启动本机任意具有普通启动入口的应用，但只允许使用系统解析出的启动入口，不接受任意组件或 Shell。它不自动处理支付、验证码和账号安全流程。权限丢失时终止相关派发并清理资源，普通聊天继续可用。

`device_open` 的执行方式由当前请求直接确定，不再使用强制用户二选一。工具协议要求模型传入 `mode`：用户明确指定前台或后台时照做；未指定时根据任务目标判断，打开或切换应用、展示页面及需要用户看到当前屏幕结果的任务传入 `main` 并使用 `MAIN_DISPLAY`，可在隔离屏独立完成且不应打扰当前屏幕的任务传入 `virtual` 并使用 `VIRTUAL_DISPLAY`。工具协议禁止仅为模式选择调用 `ask_user`；参数缺失或异常时，设备工具仍防御性回退到 `VIRTUAL_DISPLAY`，以免意外触碰主屏。工具授权与执行方式保持独立，免除模式询问不等于免除设备动作授权。两种模式都由同一前台服务维持持续通知，并复用通用三态悬浮助手。悬浮助手读取聊天页同一份 Message 与 ToolCall 记录，只显示用户可理解的状态与结果摘要，不渲染虚拟屏画面。主屏截图、节点读取和坐标动作通过设备模块的轻量控制接口暂时隐藏悬浮层，避免把自身 UI 混入界面识别或拦截动作。

设备操作显示持续通知与停止入口。能力关闭、Run 取消、会话结束或服务断开后释放对应截图、显示和输入资源。

不依赖 Root 的系统能力按剪贴板、通知和系统功能三个独立能力组注册。剪贴板支持受授权的读取、写入和清空；通知依赖 Android 通知使用权，支持读取、打开、按钮操作和清除，验证码与账户安全通知会隐藏内容并禁止自动按钮或清除；系统功能通过类型化参数打开深链接/系统面板、分享文字、读取和调整音量，并在 Android 授予“修改系统设置”后调整亮度与旋转。文件工具可对当前对话内已有文件打开系统分享面板。以上接口不接受任意 Shell、任意文件路径或未在当前对话中的文件引用。

## 7. 主题与展示层

### 7.1 统一主题解析

AppearanceSettings 持久化 themePreference：

- SYSTEM：系统浅色解析为 PAPER，系统深色解析为 GRAPHITE。
- PAPER、GRAPHITE、WARM：固定使用相应主题。

三套有效主题使用 [DESIGN.md](DESIGN.md) 的同一组语义令牌；MaterialTheme 颜色与必要的聊天专用颜色由统一映射提供。字体、间距、圆角和组件结构不随主题变化。

当前主题代码中的 Material 动态取色在正式三主题实现中关闭，避免壁纸覆盖已选配色。

### 7.2 状态归属

主题仓库可以位于 :data，用 DataStore 保存；:app 观察主题偏好与系统深浅色，在应用根部提供解析结果。

聊天 ViewModel、会话草稿、列表状态与运行时实例不以 themePreference 为 key。切换只触发展示重组，不重建模型连接、不重新绑定设备服务、不创建新会话。

首次加载设置时使用受控加载策略，避免先闪现错误配色再切换。非法或不可识别的持久化值回退为 SYSTEM。设置写入失败必须可见，不能显示已永久保存。

### 7.3 图标

UI 使用统一图标封装与主题 tint，资源从 Lucide 官方来源按需引入并锁定版本。VectorDrawable/ImageVector 转换保留路径、线宽和端点表现；依赖和许可证按实际引入记录。详见 [图标规范](DESIGN.md#7-开源图标)。

## 8. 数据、文件与模型服务

用户文件通过系统选择器获得授权，访问范围受 URI/目录约束。生成文件先写临时文件并同步，再原子发布正式产物；默认不覆盖原文件，删除和覆盖需明确范围。文件与图像工具共用产物发布器，确保 FileProvider URI 只指向已经完整写入并登记的文件。

`image_render` 是无需 Root 的独立能力组。SVG 必须自包含并带有效 `viewBox`，解析前拒绝脚本、事件属性、`foreignObject`、内嵌位图、DTD/实体以及非 `#id` 的外部引用。SVG 可原样保存，或通过 AndroidSVG 在受限尺寸的 Bitmap 上渲染为 PNG；GIF 接受 2–30 张完整 SVG 帧及逐帧时长，逐帧栅格化后使用 GIF89a 编码器生成，默认白底且不承诺透明。单帧、总文本、输出像素和动画总时长均设上限，避免模型参数造成过量内存与 CPU 占用。SVG 作为可读取的矢量源码，不直接当作模型位图输入；JPG、PNG、GIF 与 SVG 从文件卡片进入聊天页内的统一图像预览层。

模型适配层负责多轮消息、附件、正文流、思考流、工具调用与错误转换。纯聊天请求不能强制包含屏幕观察或设备会话。模型仓库保存多项连接配置和一个全局当前模型 ID；每项拥有独立的预算、思考强度字段、候选值和上次选中值。消息入队时绑定当前模型配置 ID 与思考强度，执行时从同一个 DataStore 快照读取该配置的连接和预算；已排队或已创建网关的请求不会因界面随后切换而改用其他模型。

语音转写与对话模型是两条独立连接。`VoiceInputController` 统一采集 16 kHz、16-bit、单声道 PCM 并写入缓存 WAV：OpenAI 兼容适配器以 multipart 的 `file` 与 `model` 上传；科大讯飞适配器跳过 WAV 头，按其流式 WebSocket 协议签名并发送 1280 字节音频帧。讯飞链路限制单次录音最长 60 秒，两种链路都只在得到非空转写后调用聊天工作区发送，因此转写错误不会生成空消息或触发模型请求。贴边手势在松手时把当前会话、新会话或取消结果交给控制器；新会话只在转写成功后创建，避免取消、短录音和接口失败留下空会话。

语音设置仓库在一个 DataStore 快照中保存当前格式及两套互不覆盖的连接字段。OpenAI Key、讯飞 APIKey 与 APISecret 使用 Android Keystore 主密钥分别加密；讯飞 AppID 和连接地址等非秘密字段正常持久化。切换当前格式只改变后续新录音，进行中的录音使用结束时解析到的完整配置。录音缓存无论成功、失败或取消都删除，不进入正式产物和聊天附件。

默认模型服务是产品接入工作；具体供应商、计费和账号方案尚未确定。自定义 Endpoint、模型 ID 与 Key 留在高级设置。生产密钥不得打包进 APK、写入普通日志或显示到模型消息。

Room 保存结构化记录；设置用持久化仓库；密钥使用 Android 保护机制保存引用。截图与大工具输出有短期缓存和清理上限，用户文件与正式产物有明确保留规则，不能混作可随意清理缓存。

## 9. 后台与恢复

用户发起且仍在执行的本地长任务按 Android 条件使用前台服务；可延迟工作使用系统调度。普通短聊天不依赖启动 Root 或设备前台服务。

系统杀进程、网络断开和权限变化需要在原会话解释。后台运行能力受系统限制，不承诺无限常驻或绝对准时。未来自动化复用同一执行、授权和消息记录机制。

## 10. 现有代码事实与迁移

设备工具额外提供单次授权的批量执行，模型应优先合并已能确定的连续低风险步骤。通用设置提供默认关闭的详细日志开关；开启后由核心统一日志入口向 Logcat 输出运行、模型、工具、批量步骤与设备耗时，不记录 API Key、完整消息、工具参数或截图字节。

M0 + M1a 已建立以下实现边界，验收结果在 [实施计划](PLAN.md) 中维护：

- MainActivity 使用 AppCompatActivity 承载 ChatApp，以支持 Android 应用级语言选择；旧 PrototypeScreen、DiagnosticsActivity、原型控制器与原型前台服务已删除。Application 内设备网关保持 lazy，普通聊天不会主动请求 Root。
- ChatRuntime 属于 Application 协程作用域，负责每会话串行执行、排队补充、取消、错误与启动恢复；ChatWorkspace 管理当前会话及有序草稿写入，不以主题为生命周期键。
- 新 ChatModelGateway 接受多轮 ChatTurn，通过 Flow<ModelEvent> 返回正文、思考、用量、结束和错误；OpenAiChatGateway 在流式请求中发送 `stream_options.include_usage=true`，解析 `[DONE]` 前的 usage 尾包，取消时同时关闭网络 Call。连接建立仍使用有限超时，开始响应后的读取间隔和整个 Call 不设客户端超时，避免模型长时间推理或组装大型工具参数时被本地提前截断；用户仍可随时停止任务。客户端按当前启用且可用的能力发送工具定义，使 LocalServer 原样转发思考与正文分片。
- Room AgentDatabase 升至 7：在既有聊天、思考、输入偏好、tool_calls 和 artifacts 之上新增会话置顶状态。历史列表先按置顶、再按最近更新时间排序；删除会话通过外键级联删除消息、Run、摘要、工具调用和产物索引，运行中的会话必须先停止。启动仍把未完成消息、Run 和工具调用标为 INTERRUPTED，不自动重放。
- ContextManager 使用前端配置的上下文窗口与输出预留。服务返回 usage 时显示真实输入 token；请求前按常见 BPE 特征分别估算中文/Unicode、拉丁词段、空白、JSON 标点、消息协议和工具 Schema，图片按 2048/768 缩放及 512 图块规则估算，并保留小幅安全余量。80% 触发、60% 目标；历史消息生成摘要，当前工具循环则先引用化较早结果、再折叠已完成步骤，任务继续执行。近期必要单元不静默丢弃，摘要按当前 App 语言对应的六个标题检查结构，快照另存完整来源 ID/版本、边界与前后估算，并在 Room 事务中校验后发布。
- 超长历史分块摘要再合并，每次从原始记录重建；模型输入用短消息序号引用，快照保留稳定 UUID/版本映射，明确的约束/纠正另附原文。压缩边界以前及跨会话的精确历史由受权限控制的 history_search/history_read 工具取回，ContextManager 不再绕过工具权限自动注入原文。摘要依然有损，结构检查不保证语义无损；输出截断或结构不完整不发布快照。
- 模型列表、当前模型 ID 及每项模型的连接、窗口、最大输出、思考强度字段、自定义等级列表与选中强度由同一 DataStore 快照加载。思考强度默认选中内置“关闭”，请求使用协议值 `none` 明确关闭深度思考；用户选择“不指定”时保存显式空值且不发送该字段，由模型服务自行决定。每个 API Key 使用同一 Android Keystore 主密钥分别加密，密文随所属模型配置保存；旧版单模型字段首次启动时无损迁移为第一项。未保存预算时默认使用 180,000 Token 总上下文和 40,000 Token 最大输出，用户仍需按服务实际能力调整；最大输出同时从输入预算中预留，思考模型可能将思考与正文共同计入其中。输入区显示“当前输入 + 最大输出 / 总窗口”，估算值带“≈”，达到 80% 使用警示色。
- 语音设置提供 OpenAI 兼容格式和科大讯飞语音听写 WebAPI 两种独立配置及一个当前格式。聊天页和悬浮按钮复用 Application 级语音状态，确保同一时刻只有一路录音或转写；悬浮长按录音期间前台服务临时声明麦克风类型，结束后恢复普通服务类型。贴边手势使用独立的纵向累计位移、48dp 切换阈值和 10dp 迟滞，上滑取消、下滑新会话、回中恢复当前会话发送，跨区时提供轻触觉反馈。
- AgentExecutionSettingsRepository 通过独立 DataStore 持久化全局单轮最大步骤，未配置或持久值异常时使用 99，合法范围为 1–999。ChatRuntime 在每个新任务开始时读取并校验一次，限制连续工具调用轮数；执行中的任务固定使用启动时快照，避免设置变更中途改变运行边界。
- AppearanceRepository 持久化 SYSTEM/PAPER/GRAPHITE/WARM；Theme.kt 使用统一语义色，不启用动态取色。输入、焦点、历史列表与请求不因主题重建。Lucide 0.468.0 矢量与完整 ISC/MIT 许可已落盘。
- app 构建 minSdk 为 24、targetSdk 为 36；构建配置不等于所有设备能力已覆盖这些版本。

迁移保留已有可用的设备会话、取消、存储和模型连接基础，删除不再使用的原型诊断页面。Root 只在用户主动打开通用设置开关时请求；本机没有可执行的 Root 环境时开关不可编辑。每个能力继续通过独立接口接入。

已注册的可执行工具包括历史搜索/原文读取、对话附件读取/文本生成/文件分享、SVG/PNG/GIF 图像渲染、客户端互联网搜索/公开网页读取、设备会话识别/动作/复杂触控/状态等待，以及剪贴板、通知和系统功能。界面按提供者能力组展示，每组独立保存启用状态及 REQUEST_APPROVAL/FULL_ACCESS，界面分别显示为“每次询问/始终允许”。关闭或当前不可用的工具不会提供给模型；降级能力保留可执行的授权或设置入口。模型请求动态包含设备当前时间与时区；工具提示要求复制真实标识、避免无变化的失败重试，并明确设备识别、文件引用、历史原文和网页来源的调用顺序。授权面板使用单独的用户文案和参数摘要，不显示模型提示、原始 JSON 或内部 ID。网络搜索与正文提取在 App 内执行，标题、URL、摘要和读取正文随 ToolCall 保存，来源卡片只打开已通过公网地址检查的 HTTP(S) URL。网络连接只使用同一次 DNS 解析中筛出的公网地址，每级重定向重新校验；DNS 故障、HTTP 错误与内网拦截分别返回真实原因。系统选择器附件继续保存持久 URI 授权；用户图片与设备识别截图在客户端限尺寸并转为单步临时多模态请求内容，不把 Base64 写入数据库。生成文件接受不含路径分隔符和控制字符的安全 Unicode 文件名。超过 12000 个 UTF-8 字节的普通工具结果由 ToolCall 保存完整内容，当前模型只接收片段与结果引用，history_read 可按 offset 继续读取；界面识别节点结果例外，单步决策后只保留失效占位符。

文本产物先写同目录临时文件并同步后原子改名，再登记到 Room。页面通过受限 FileProvider URI 提供应用内预览、系统分享、删除和继续加工；同名产物自动保留新版本，不覆盖旧文件。JPG、PNG、GIF 和 SVG 由独立图片解码器直接读取受控产物 URI，显式注册 SVG 及高低 Android 版本对应的 GIF 解码器，不再经 WebView 或 Base64 中转。HTML 最多读取 1 MB，注入限制外部资源、表单和基础地址的 CSP 后交给禁用脚本、文件和 ContentProvider 访问的 WebView；请求拦截器只放行 `data:`/`about:`，所有链接跳转均被拦截。其它文件保持最多 100,000 字符的文本预览。外部图片/文本分享的临时 URI 会复制到独立受控目录，用户选择新会话或已有会话后成为草稿附件；未被草稿、消息或待处理分享引用的导入副本会被回收。模型图片缓存有容量和时限，启动时同时清理异常临时文件、孤立产物与缺失记录。模型服务每次返回 usage 时，ChatRuntime 将该请求最后一份输入/输出 Token 交给独立 DataStore，以稳定的模型配置 ID 累计；名称或远端模型 ID 更新只刷新显示元数据，删除配置不删除历史用量。没有真实 usage 的请求不写入累计值。数据管理页展示上述分模型用量，也可以人工触发同一套安全清理并显示释放量；任务执行期间拒绝人工清理，避免与附件读取或工具文件写入竞争。设备会话限定在创建它的 Run 内，正常结束、失败与停止都执行兜底关闭。后台不承诺进程常驻，系统结束进程后显式中断且不重放外部动作。实际验证状态见 [实施计划](PLAN.md)。
