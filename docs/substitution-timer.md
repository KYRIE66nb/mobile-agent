# 火影替身计时器（Substitution Timer）

火影忍者手游「替身术」冷却的本地观察/推断/计时悬浮工具。**纯本地识别**：不调用大模型、Laya/Jev 或任何远端服务；截图不落盘不上传；不做自动战斗/连点/按键注入/读内存/Hook。只观察像素并显示推测倒计时。

## 使用流程

1. 设置 → 「替身计时」Tab：确认"启用替身计时"+"打开 App 时自动进入启动流程"（默认开），选择目标游戏（从已安装应用列表选火影渠道服包名）。
2. 打开 App → 自动弹系统录屏授权（MediaProjection，每次会话授权一次，可选单应用共享选"火影"）。
3. 授权后进入待机；进入游戏对局 → 自动开始识别，游戏上方出现倒计时胶囊。
4. **首次必须校准**：在游戏画面停留片刻后回到设置页 → "豆槽校准"用最后一帧游戏画面 + 绿/橙滑杆框出双方豆槽 → 保存。未校准前不会显示"识别中"。
5. 通知栏提供 暂停本次 / 停止；离开游戏自动隐藏计时。

## 检测原理（独立实现）

- 采集：MediaProjection + ImageReader（RGB_8888），mediaProjection 类型前台服务，只留最新帧、慢设备丢帧。
- 每帧对左右豆槽矩形（归一化坐标，含内容区黑边映射）等分 N 格，只取格中心 60% 区域做 7×7 逐像素分类：命中点亮青蓝盒占比 ≥12% → LIT、命中熄灭暗青盒 ≥40% → EMPTY，否则 UNKNOWN（均值池化会让亮豆被背景稀释——逐像素表决不稀释）。
- 连续 confirmFrames(默认3) 帧一致才确认计数；仅稳定 **n→n−1** 产生"疑似替身"候选并计时 `endAt=eventAt+cooldownMs`（SystemClock 单调钟，锚定在候选计数首次观测帧）。
- 涨豆、多豆跳变、爆闪/遮挡/UNKNOWN 不触发；候选去重窗 800ms；冷却中再掉豆标 conflict 不静默覆盖；无效帧超 2s 或离开/回到游戏 → 重建基线。
- 事件端三层兜底：掉豆候选先进 2.5s 悬置验证（回弹即撤销）；高位短驻 <2.5s 后落回原值判为涨豆/闪光抖动不算替身；悬置未决再掉豆判级联消耗。
- 盲窗重建检测：特效/遮挡导致帧无效 >2s 重置基线时记录丢失前计数；重建后净掉 1 颗补发替身候选（仍走悬置验证）、净掉多颗报歧义、涨豆不产事件、未决候选弹回则追加撤单。
- 悬浮窗"重置"=清计时+重建基线+解除暂停；授权后服务若被后台启动限制拦截，授权令牌暂存、回 App 自动续起。
- 识别延迟 ≈ confirmFrames × frameIntervalMs（默认 3×80ms ≈ 0.24s），倒计时从候选首见帧起算。

## 已知边界

- 主动扣豆技能/特殊机制与替身同为 −1 → 无法区分，计时一律标"疑似"，可用悬浮窗"重置"纠错。
- 冷却默认 15s 为决斗场经验值，设置页可调；布局默认坐标只是校准起点，未校准不进入识别。
- 仅验证标准决斗场布局思路；特殊忍者/多豆形态/非横屏未适配。
- 需要"使用情况访问"权限检测游戏前台（PACKAGE_USAGE_STATS 已声明，设置-能力页可引导）；悬浮窗需 overlay 权限；通知权限拒绝不影响识别，仅隐藏常驻通知。
